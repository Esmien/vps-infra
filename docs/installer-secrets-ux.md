# Установщик: сбор секретов и стартовых констант (план)

Статус: **v1 реализован** (2026-11-03): интерактивный сбор через `/dev/tty`, отчёт `secrets-*.enc` + ключ отдельным сообщением, шаг `report` в конце установки. Осталось: реестр констант отдельным файлом и первичная установка без архива. Записано по формулировке владельца 2026-11-03.

## Проблема сейчас

Секреты приходят «снаружи» — файлом `/root/bootstrap.env`, который владелец готовит руками
до запуска. Из-за этого:

- состав констант нигде не описан, кроме кода установщика; забыл переменную — падение на середине;
- нет интерактивного сбора: значения приходится знать заранее;
- самогенерируемые секреты (`SECRETS_KEY`, пароли БД/Redis, `SEARXNG_SECRET_KEY`) вводятся руками,
  хотя их должен придумывать установщик;
- после установки у владельца нет простого способа получить обратно полный набор
  (что куда легло) — только лазить по `.env` на сервере.

## Целевая концепция

### 1. Константы вместо файла

Каждая необходимая константа описывается в коде установщика записью вида:
`имя`, `человеческое описание (зачем нужна)`, `тип` (секрет/значение), `можно ли автогенерировать`,
`обязательна ли`, `способ проверки`.

Никакого «положи `bootstrap.env` и молись»: перечень формируется из этого реестра.

### 2. Интерактивный сбор в CLI

Перед установкой установщик спрашивает всё, что ему нужно, по одному пункту:
имя, описание, зачем нужно, пример, `[Enter]` — принять значение/сгенерировать.
Вопросы идут через `/dev/tty` (stdin занят потоком `curl … | bash`) — механизм `ask()` уже есть.

### 3. Автогенерация для самогенерируемого

Пароли БД, Redis, `SECRETS_KEY`, ключи шифрования, внутренние API-ключи — предлагаются
сгенерированными по умолчанию (Enter = согласиться). Пользователь может ввести своё.
Внешние токены (GitHub, Telegram-боты, Cloudflare) автогенерировать нельзя — только запрос.

### 4. Установка после сбора

Сначала полный сбор, потом все остальные шаги. Никаких «полуустановок», где не хватает
одной переменной и падение случается на середине.

### 5. Отчёт с секретами в Telegram после успешной установки

После **успешного** завершения — сообщение в бот-нотификатор со **скрытым текстом**
(Telegram spoiler `||…||`): весь набор констант, разбитый на группы так, как он лежит по файлам
(`ai/.env`, `notifications/.env`, `hermes/.env`, БД, TLS и т.д.).
Плюс, если включено, — зашифрованный файл с тем же содержимым.

### 6. Два режима запуска

**Полный (интерактивный).** Установщик сам спрашивает всё, что нужно → установка → отчёт в TG.

**Минимальный (ручной).** Указываются только самые необходимые константы, необходимые чтобы
дотянуться до архива секретов и запуститься. Далее:

1. установка идёт;
2. после установки установщик проверяет, пришёл ли в бот шифрованный файл с секретами;
3. если файл есть — автораспаковка (как сейчас), вопросов не задаём;
4. если файла нет — добираем недостающее у пользователя интерактивно (п. 2–3).

То есть «минимальный режим» — это восстановление из архива, а «полный» — первичная установка
с нуля, когда архива ещё нет.

## Что придётся поменять

- `install.py`: реестр констант, шаг `secrets` → интерактивный мастер, генераторы значений,
  проверка формата (токен бота, GitHub PAT, CF API-токен);
- `bootstrap.sh`: не требовать `bootstrap.env`, пробрасывать режим (`--interactive` / `--minimal`);
- доставка отчёта: сообщение со спойлерами + опционально документ с зашифрованным архивом;
- обратная совместимость: если `bootstrap.env` есть — работаем как раньше (не ломать текущий флоу);
- ключевой риск: секреты в Telegram. Отчёт отправляется **только** в личный чат владельца,
  в групповые чаты — никогда. Спойлер — не шифрование, поэтому общий чат исключаем.

## Решения владельца (2026-11-03)

1. **Формат отчёта:** в Telegram уходит **файл** с секретами (зашифрованный) + **ключ расшифровки отдельным
   сообщением**, чтобы ключ можно было удалить из чата сразу после сохранения. К сообщению прикладывается
   короткая инструкция по расшифровке (какая команда, чем). В самом тексте сообщения секретов нет —
   только «файл + ключ + инструкция».
2. **Триггер отчёта:** конец всех шагов установки («всё готово» в терминале). Аудит топологии — отдельно,
   по запросу владельца (шаг `postcheck` удалён 2026-11-06), это не часть отправки отчёта.
3. **Флаг «не отправлять» не нужен** — уведомление отправляется всегда.

## Решено по предыдущей нумерации (вопросы 1–3)

- отчёт: файл + ключ отдельно, рекомендация удалить сообщение с ключом, инструкция по расшифровке;
- «успешная установка» = все шаги пройдены;
- отправлять всегда.
