# Аватарки моделей — статический кэш для nginx

Зачем: SPA Open WebUI запрашивает иконки моделей на холодном старте раньше,
чем восстановлена сессия. Ответ `401` заставляет клиент подменить картинку
дефолтным логотипом, и повторной попытки в клиенте нет — иконки «исчезают»
до полной перезагрузки приложения.

Решение: те же файлы отдаёт nginx из `/var/cache/owui-avatars` без
авторизации (`location = /api/v1/models/model/profile/image` с `try_files`,
фолбэк — проксирование в WebUI, как раньше).

Состав:

- `sync-avatars.py` — выгружает `webui_db.model.meta.profile_image_url`
  (`data:image/...`) в `/var/cache/owui-avatars/<id>.<ext>`. Файлы только
  дописываются/обновляются, ничего не удаляется; неизменённые не трогает.
  На хосте: `/usr/local/bin/owui-avatar-sync.py` + `owui-avatar-sync.timer`
  (каждые 15 минут). Источник истины — база, кэш вторичен.
- nginx-блок — `vps-infra/assets/host/etc/nginx/conf.d/ai.esmien.ru.conf`.
- восстановление записи — `vps-infra/assets/host/{bin,systemd}`.

Ограничение: аватарки становятся доступны без авторизации по id модели
(это логотипы, не пользовательские данные).
